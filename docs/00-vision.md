# 00 — Project Vision

## Product Name

KUNNA

## Document Purpose

This document defines the initial vision for KUNNA as part of the **I1 — Inception Package**.

The purpose of this artifact is to clarify the product direction before writing production code. It connects the original UX/UI prototype with the current software engineering process.

## Product Idea

KUNNA is a digital product designed to support mothers, fathers, and caregivers with accessible content related to children's rights, positive parenting, and daily caregiving practices.

The product domain includes:

- Derechos de niñas y niños.
- Crianza positiva.
- Tips diarios.
- Audio content.
- Bookmarks.
- Downloads.
- Search.
- User profile.
- Content sharing.

## Vision Statement

KUNNA aims to become a trusted digital companion for caregivers who need practical, accessible, and understandable guidance about child care, children's rights, and positive parenting.

From a software engineering perspective, KUNNA is being rebuilt as a documented, iterative, object-oriented software project based on an original UX/UI prototype.

The goal is not only to build an application, but to demonstrate the complete process of transforming a product idea into a structured software engineering project.

## Background

KUNNA started as a UX/UI prototype created several years ago during a design and user experience learning process. The original prototype won first place in a course and included a visual flow focused on caregivers and child-related content.

This repository does not treat KUNNA as an old app to recreate quickly. Instead, it treats KUNNA as a personal software engineering project intended to show professional growth, technical reasoning, and portfolio evidence.

## Problem

Caregivers often need clear, practical, and trustworthy information about children's rights, positive parenting, and daily care practices.

However, this information can be:

- Fragmented across different sources.
- Difficult to understand.
- Too general or disconnected from daily caregiving situations.
- Hard to revisit when needed.
- Not always presented in a format suitable for quick consultation.

## Target Users

The initial target users are:

- Mothers.
- Fathers.
- Caregivers.
- People responsible for the daily care and protection of children.

In Spanish product/domain language, these users can be described as:

- Madres.
- Padres.
- Cuidadores.
- Personas responsables del cuidado diario de niñas y niños.

## User Needs

Initial user needs include:

- Accessing understandable content about children's rights.
- Receiving practical parenting tips.
- Saving useful content for later.
- Searching for specific topics.
- Listening to audio-based content.
- Downloading relevant resources.
- Sharing useful information with others.
- Managing a simple user profile.

## Expected Product Outcome

The expected product outcome is to provide caregivers with a more accessible way to consult, save, and share practical content related to children's rights and positive parenting.

At this stage, the product outcome is not a finished application. The expected outcome of the Inception phase is clarity.

## Expected Engineering Outcome

The expected engineering outcome is to demonstrate the ability to transform a UX/UI prototype into a professional software engineering project through:

- Product reasoning.
- User goal analysis.
- Use-case modeling.
- Requirements documentation.
- Glossary and domain language.
- Risk identification.
- UML modeling.
- Object-oriented analysis.
- Documented decisions.
- Progressive Java implementation.

## Initial Scope

The initial scope of the project includes:

- Defining the product vision.
- Identifying user goals.
- Creating an initial use case model.
- Writing a supplementary specification.
- Creating a glossary.
- Identifying initial risks.
- Defining the development plan.
- Defining the development framework.
- Creating an AI collaboration policy.
- Maintaining a decision journal.
- Creating an initial product backlog.
- Documenting the first architecture decision record.

## Out of Scope for Now

The following items are intentionally out of scope during the current phase:

- Production code.
- Final UI implementation.
- Spring Boot API.
- Database design.
- Authentication implementation.
- Mobile application development.
- Deployment.
- Advanced architecture decisions.
- Full content management system.
- Final visual redesign.

## Strategic Direction

KUNNA follows a product-first and documentation-first approach.

This means:

- The problem comes before the solution.
- User outcomes come before implementation details.
- Software artifacts guide future code.
- Decisions must be documented.
- AI can support analysis and drafting, but final decisions remain human.
- No code should be accepted unless it can be explained.

## Relationship with the Inception Phase

This vision document belongs to the **I1 — Inception Package**.

The goal of Inception is to define enough clarity to decide what the project is, why it matters, who it serves, what risks exist, and what should be explored before implementation.

In this phase, success means having a strong foundation, not having a finished application.

## Success Criteria for This Vision

This vision will be considered useful if it helps answer:

- What is KUNNA?
- Why does KUNNA exist?
- Who is KUNNA for?
- What problem does KUNNA address?
- What is the initial project scope?
- What is intentionally out of scope?
- How does this project support software engineering learning and portfolio development?

The following questions remain open for future analysis:

- Which use cases should be prioritized first?
- What content categories should KUNNA support initially?
